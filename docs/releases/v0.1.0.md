# RepoPilot v0.1.0

RepoPilot v0.1.0 is the first portfolio release of the auditable `issue2patch` CLI. It turns a failing issue into a tested unified diff while keeping the source repository unchanged.

## Live evidence

The first successful DeepSeek + Docker run is preserved in the GitHub Actions
history. Published evaluation reports and live evidence are the source of truth;
the project does not use a scripted replay as a product demo.

## Evaluation

- Suite: 10 fixed broken repositories, 3 independent runs each
- Machine-readable report: [`eval-results/eval-report.json`](../../eval-results/eval-report.json)
- Human-readable report: [`eval-results/eval-report.md`](../../eval-results/eval-report.md)
- Strict success: Agent success + tests pass + original unchanged + no non-allowlisted edits

Do not publish this release until both report files come from a completed credentialed run. Mock results must never populate the live metrics.

## Highlights

- Strict structured actions with no model-provided shell commands
- SHA-256 guarded, preflighted, atomic multi-file patches
- Temporary working copies and source-repository snapshot verification
- Network-disabled, non-root, read-only Docker test sandbox with resource limits
- Redacted JSONL audit traces without source, secrets, environment, or hidden reasoning
- Deterministic offline tests plus opt-in real Responses API verification
- Repeatable JSON and Markdown Agent evaluation reports

## Known limitations

- The benchmark currently contains small, single-file Python repairs.
- The CLI returns a diff; it does not apply, commit, push, or create a pull request.
- Live results depend on model snapshots, rate limits, and service conditions.
- Docker is a risk-reduction boundary, not a guarantee against container-runtime vulnerabilities.
